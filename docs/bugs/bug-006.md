# BUG-006 — Public website and documentation need a hosted HTTPS URL

- Status. Open product-owner follow-up.
- Priority. P2.
- Reported by the product owner on 2026-11-02 during review of `dhivon-brand-site-docs`.
- Reviewed implementation. `fe930285c9c18bafbab36a72635b600aba47c7b5`, with verification checkpoint `eae1965b5154e701f2974c79d2b3d370d9aebc42`.

## Reported behavior

The delivered website and documentation are opened through the development
preview at `http://127.0.0.1:4173/`. The OAuth guide, for example, is currently
shown at `http://127.0.0.1:4173/docs/oauth.html`. This address points to the
viewer's own computer and requires that local preview process. It cannot serve
as the shared product website or documentation address.

The owner requested a hosted URL for the public website and documentation.

## Evidence

- `apps/site/preview.ts` binds its development HTTP server to `127.0.0.1:4173`.
- The README's product website section directs readers to that local preview.
- `apps/site/build.ts` produces independently hostable static output.
- The approved specification left the hosting vendor and public domain open.
  The release report records hosting as follow-up administration.

## Expected behavior and acceptance criteria

1. Choose and record the approved hosting target and canonical HTTPS origin for
   Dhivon MCP Gateway's public product website and documentation.
2. Deploy the static website and guides at that origin. A reader on another
   device can open them without running the repository or a local server.
3. Verify direct guide URLs, including `/docs/oauth.html`, page refresh, internal
   links, anchors, SVGs and locally bundled fonts through the hosted origin.
4. Use the hosted URL in the public website handoff and publication instructions.
   Keep the local address explicitly labeled as a development preview.
5. Record the deployed revision, HTTPS URL and external access verification.

## Scope and implementation handoff

This request concerns public website and documentation hosting. The native Mac
management interface and OAuth redirect callback have intentional loopback
addresses. Their security and protocol requirements remain applicable.

The current delivery assumed no hosting vendor or public domain. Select the
hosting target and origin when planning this follow-up. Logging this report
records the owner's request. Deployment and closure require a verified hosted
result.
