# BUG-005: User management needs email, password and name

- Status: Open — reported; implementation not started.
- Reported by: Product owner, 2026-10-15.
- Priority: P2.
- Source: “in user management it needs to be email, password and name.... log that as a bug”

## Current behavior

Administrator user creation provides Username and Password, alongside Role.
There are no separate Email or Name fields. The public user contract contains
`username`, and user edits only support role/active state.

Evidence at reviewed product commit `52c288b`:
- `apps/web/src/admin/identities.tsx:97` initializes the account field from username;
  creation sends username/password at lines112–113 and renders Username at line164.
- `crates/gateway-core/src/contracts.rs:15` defines UserInfo without email/name;
  UserCreate at line32 likewise lacks those fields.

## Expected behavior and acceptance criteria

1. Administrator user creation includes required **Name**, **Email** and **Password**
   fields, with clear validation feedback.
2. Store and return name/email as distinct profile fields; user management displays
   them and supports appropriate profile edits.
3. Passwords remain write-only, securely hashed, absent from user list/read responses,
   and changed through the existing protected password/reset flow.
4. Update the database, Rust/TypeScript contracts, UI and relevant tests together;
   preserve stable user IDs, grants, memberships and credential ownership.
5. During implementation planning, specify email uniqueness/normalization, login
   behavior and migration for existing username-only accounts.

This is a product-owner requirement correction to the initial username/password
baseline. Logging it does not revise the approved specification, authorize an
implementation run, or approve the pending MVP completion proposal.
